1.2. USER LOGIN
--------------------------------------------------------------------------------
File: Frontend/src/pages/Auth/Login.tsx
Route: "/login"
Access: Public / Unauthenticated

A. DATA IN (Incoming Inputs)
   - User Form Controls:
     * role: "applicant" | "employer" (Tab toggle)
     * email: string (User email address)
     * password: string (User plaintext password)
     * rememberMe: boolean (Checkbox)

B. DATA OUT TO BACKEND (API Request)
   - Endpoint: POST /api/auth/login
   - Request Headers: { "Content-Type": "application/json" }
   - Payload:
     {
       "role": "applicant" | "employer",
       "email": "user@example.com",
       "password": "secretPassword",
       "rememberMe": true | false
     }

C. DATA IN FROM BACKEND (API Response)
   - Response Payload (Success - 200 OK):
     {
       "message": "Login successful.",
       "token": "jwt_token_string",
       "user": {
         "id": 12,
         "email": "user@example.com",
         "role": "applicant" | "employer",
         "first_name": "Maria",
         "last_name": "Santos",
         "full_name": "Maria Santos",
         "business_name": "Tech Corp (if employer)",
         "businessName": "Tech Corp"
       }
     }
   - Response Payload (Error - 400/401/500):
     {
       "message": "Invalid email or password."
     }

D. DATA OUT (Client Persistence & Routing)
   - localStorage:
     * Key: "elitecruit-user"
     * Value: JSON.stringify(normalizedUser)
   - Redirection:
     * If role === "applicant" -> "/applicant-dashboard#section-overview"
     * If role === "employer"  -> "/employer-dashboard"

1.3. USER REGISTRATION
--------------------------------------------------------------------------------
File: Frontend/src/pages/Auth/Create-Account.tsx
Route: "/create-account"
Access: Public / Unauthenticated

A. DATA IN (Incoming Inputs)
   - User Form Controls:
     * role: "applicant" | "employer"
     * firstName: string (Applicant only)
     * middleName: string (Applicant only, optional)
     * lastName: string (Applicant only)
     * businessName: string (Employer only)
     * email: string
     * password: string (Checked for: 8+ chars, uppercase, lowercase, digit)
     * confirmPassword: string
     * agreeTerms: boolean

B. DATA OUT TO BACKEND (API Request)
   - Endpoint: POST /api/auth/register
   - Request Headers: { "Content-Type": "application/json" }
   - Payload:
     {
       "role": "applicant" | "employer",
       "email": "user@example.com",
       "password": "StrongPassword123",
       "firstName": "Maria",
       "middleName": "G.",
       "lastName": "Santos",
       "businessName": "Santos Logistics Inc"
     }

C. DATA IN FROM BACKEND (API Response)
   - Response Payload (Success - 201 Created):
     {
       "message": "Account created successfully.",
       "user": {
         "id": 14,
         "email": "user@example.com",
         "role": "applicant" | "employer"
       }
     }
   - Response Payload (Error - 400/409):
     {
       "message": "An account with this email already exists."
     }

D. DATA OUT (Client State & Feedback)
   - Form field error messages (Password strength meter: Weak/Fair/Good/Strong).
   - Success notification message and auto-routing to "/login".

2.1. APPLICANT DASHBOARD
--------------------------------------------------------------------------------
File: Frontend/src/pages/Applicant/Applicant-Dashboard.tsx
Route: "/applicant-dashboard"
Access: Authenticated Applicant

A. DATA IN (Incoming Inputs)
   - Session Data: localStorage.getItem("elitecruit-user") -> { id, role, email, ... }
   - User UI State:
     * Section Navigation: Overview, Smart Matches, My Applications, Job Invitations
     * Applications status filter: "all" | "pending" | "shortlisted" | "approved" | "denied"
     * Keyword search query
     * Modal trigger: Job Details Modal, Apply Confirmation, FAQ Drawer

B. DATA IN FROM BACKEND (API Queries)
   1. GET /api/applicants/:userId/applications
      Response: { "applications": [ { id, job_post_id, job_title, status, submitted_at, salary_min, salary_max, ... } ] }
   2. GET /api/applicants/:userId/invitations
      Response: { "invitations": [ { id, job_post_id, employer_user_id, status, custom_message, job_title, business_name, ... } ] }
   3. GET /api/applicants/:userId/profile
      Response: { "profile": { first_name, last_name, desired_job_title, work_arrangement, expected_salary, city, skills, qualifications, certifications } }
   4. GET /api/job-posts
      Response: { "jobPosts": [ { id, title, location, salary_min, salary_max, work_arrangement, required_skills, ... } ] }
   5. GET /api/employers/:employerUserId/faqs
      Response: { "faqs": [ { id, question, answer, question_type, is_active } ] }

C. DATA OUT TO BACKEND (Mutations / Submissions)
   1. Job Application Submission:
      - Endpoint: POST /api/applicants/:userId/applications
      - Payload: { "job_post_id": 105 }
      - Response: { "message": "Application submitted successfully." }
   2. Job Invitation Response:
      - Endpoint: PUT /api/invitations/:invitationId/respond
      - Payload: { "status": "accepted" | "declined" }
      - Response: { "message": "Invitation response recorded." }

D. DATA OUT (Rendered UI / Client Computations)
   - Metrics calculation: Total Applications, Under Review, Shortlisted, Smart Matches.
   - Algorithmic Match Score computation (0-100%) based on applicant profile vs. job posting.
   - Live scroll-sync navigation tracking via IntersectionObserver.
   - Applications progress table with color-coded status badges.
   - Direct job invitations alert cards with 1-click Accept / Decline buttons.

2.3. APPLICANT PROFILE & CREDENTIALS (3 DISTINCT SECTIONS)
--------------------------------------------------------------------------------
File: Frontend/src/pages/Applicant/ApplicantProfile.tsx
Route: "/my-profile"
Access: Authenticated Applicant

A. DATA IN (Incoming Inputs)
   - Session Data: localStorage.getItem("elitecruit-user")
   - Section 1 (Personal & Contact Information):
     * first_name, middle_name, last_name, email, phone (+63 numbers-only), city (Cavite dropdown), address
     * Pinpoint Map Coordinates: latitude, longitude (Interactive Leaflet Map Modal)
   - Section 2 (Career Targets & Job Preferences):
     * desired_job_title (standard dropdown of IT/CS roles)
     * work_arrangement ("Remote" | "On-Site" | "Hybrid")
     * expected_salary (PHP monthly formatted currency)
     * years_of_experience (Overall Career Level: Entry, Junior, Mid, Senior, Lead)
   - Section 3 (Competencies, Experience & Documents):
     * Core Technical Skills: Array of up to 5 items, each with individual Years of Experience (< 1 yr, 1 yr, 2 yrs, 3 yrs, 4 yrs, 5+ yrs)
     * Educational Qualifications: Array of up to 5 items, each with individual Years of Experience
     * Professional Certifications: Array of up to 5 items, each with individual Years of Experience
     * Resume / CV Document: File object (PDF, DOC, DOCX up to 10 MB)

B. DATA IN FROM BACKEND (API Queries)
   1. GET /api/applicants/:userId/profile
      Response: Full applicant profile record (first_name, last_name, email, phone, city, address, desired_job_title, work_arrangement, expected_salary, years_of_experience, skills, qualifications, certifications, latitude, longitude, resume_path).
   2. GET /api/applicants/:userId/resume
      Response: Streamed PDF/Word binary document from database BYTEA storage for direct in-browser viewing.

C. DATA OUT TO BACKEND (Mutations)
   1. Update Core Profile & Career Preferences:
      - Endpoint: PUT /api/applicants/:userId/profile
      - Payload: { first_name, middle_name, last_name, email, phone, city, address, desired_job_title, work_arrangement, expected_salary, years_of_experience, latitude, longitude }
   2. Update Competencies with Experience (Max 5 per category):
      - Endpoint: PUT /api/applicants/:userId/tags
      - Payload: { field: "skills" | "qualifications" | "certifications", items: ["React (2 years)", "Node.js (1 year)"] }
   3. Upload Resume Document:
      - Endpoint: POST /api/applicants/:userId/resume
      - Payload: FormData containing "resume" File (binary stored in PostgreSQL BYTEA)
   4. Remove Resume Document:
      - Endpoint: DELETE /api/applicants/:userId/resume

D. DATA OUT (Rendered UI)
   - Sticky 3-section tab navigation with active step highlighting and single-section view (unselected sections remain hidden).
   - Section 1: Personal & Contact Information (Name, email, phone, city, address).
   - Section 2: Career Targets & Preferences + Interactive Pinpoint Map radar location card.
   - Section 3: Category managers capped at 5 items with dynamic count badge ("X / 5 Selected") and inline experience selectors (Core Technical Skills, Educational Qualifications, Professional Certifications).
   - Integrated ApplicantChatbotDrawer in header.
   - Resume tracker with 1-click View and Delete actions.

4.1. REAL-TIME MESSAGES
--------------------------------------------------------------------------------
File: Frontend/src/pages/Common/Messages.tsx
Route: "/messages"
Access: Authenticated Users (Applicant or Employer)

A. DATA IN (Incoming Inputs)
   - Session Data: localStorage.getItem("elitecruit-user") -> detected role & user ID
   - User Chat Controls:
     * Selected Thread: ThreadItem (Clicked conversation from left list)
     * Filter Tabs: "all" | "applied" | "recruited"
     * Search Query: string (Filters threads by participant name)
     * composeText: string (New message content)
     * Send Message Action: Form submission or Enter key

B. DATA IN FROM BACKEND (API Queries)
   1. GET /api/users/:userId/messages
      Response: Array of threads with last message preview, participant names, and invitation statuses.
   2. GET /api/messages/threads/:threadId
      Response: Array of ChatMessage objects for the conversation history.
   3. GET /api/applicants/:applicantUserId/profile (If viewer is employer)
      Response: Candidate profile summary rendered in right info pane.
   4. GET /api/employers/:employerUserId/profile (If viewer is applicant)
      Response: Company information rendered in right info pane.
   5. GET /api/employers/:employerUserId/faqs (If viewer is applicant)
      Response: Employer FAQs drawer.

C. DATA OUT TO BACKEND (API Mutation)
   - Endpoint: POST /api/messages/send
   - Payload:
     {
       "thread_id": 8,
       "sender_user_id": 12,
       "receiver_user_id": 45,
       "message_text": "Hello, thank you for reviewing my application."
     }

D. DATA OUT (Rendered UI)
   - Thread list with "Applied" / "Recruited" status badges.
   - Message bubbles with sender identification and formatted timestamps.
   - Auto-scroll to bottom of conversation upon message reception or dispatch.
   - Contextual right drawer showing candidate resume or company overview.

4.2. NOTIFICATIONS CENTER
--------------------------------------------------------------------------------
File: Frontend/src/pages/Common/Notifications.tsx
Route: "/notifications"
Access: Authenticated Users (Applicant or Employer)

A. DATA IN (Incoming Inputs)
   - Session Data: localStorage.getItem("elitecruit-user")
   - Filter Controls: "all" | "read" | "unread"
   - User Actions:
     * Mark single notification as read (Click)
     * "Mark all as read" button
     * Notification Settings Modal (Email & Push toggles)

B. DATA IN FROM BACKEND (API Query)
   - Endpoint: GET /api/users/:userId/notifications
   - Response Payload:
     {
       "notifications": [
         {
           "id": 501,
           "user_id": 12,
           "type": "new_application" | "job_invitation" | "application_shortlisted" | "application_approved" | "application_denied" | "message" | "feedback",
           "title": "Application Shortlisted",
           "body": "Your application for Senior Web Developer has been shortlisted.",
           "is_read": 0,
           "created_at": "2026-08-31T12:30:00Z"
         }
       ]
     }

C. DATA OUT TO BACKEND (API Mutations)
   1. Mark Single Notification Read:
      - Endpoint: PUT /api/notifications/:id/read
   2. Mark All Notifications Read:
      - Endpoint: PUT /api/notifications/mark-all-read
      - Payload: { "user_id": 12 }

D. DATA OUT (Rendered UI & Navigation Badges)
   - Dynamic calculation of unreadCount = notifications.filter(n => !n.is_read).length.
   - Notifications grouped by category and date.
   - Click navigation to target page (e.g. clicking invitation redirects to dashboard invitations).
   - Sidebar notification badge dynamically reflects unreadCount (hidden when 0).

4.3. FEEDBACK & RATINGS
--------------------------------------------------------------------------------
File: Frontend/src/pages/Applicant/Applicant-Feedback.tsx
Route: "/feedback"
Access: Authenticated Users (Applicant or Employer)

A. DATA IN (Incoming Inputs)
   - Session Data: localStorage.getItem("elitecruit-user") -> role detected
   - Feedback Form Inputs:
     * selectedTargetId: number (Company ID if applicant, or Candidate ID if employer)
     * rating: number (1 to 5 stars)
     * comments: string (Detailed review notes)

B. DATA IN FROM BACKEND (API Queries)
   1. For Applicants:
      - Endpoint: GET /api/applicants/:userId/eligible-feedback-employers
      - Response: Array of employers where the applicant has completed an interview or received an application decision.
   2. For Employers:
      - Endpoint: GET /api/employers/:userId/applications
      - Response: Filtered list of applicants with shortlisted, approved, or recruited status.

C. DATA OUT TO BACKEND (API Mutations)
   1. Applicant Submitting Employer Feedback:
      - Endpoint: POST /api/applicants/:userId/company-feedback
      - Payload:
        {
          "employer_user_id": 18,
          "rating": 5,
          "comments": "The interview process was transparent, timely, and professional."
        }
   2. Employer Submitting Candidate Feedback:
      - Endpoint: POST /api/employers/:userId/applicant-feedback
      - Payload:
        {
          "applicant_user_id": 44,
          "rating": 5,
          "comments": "Candidate was very well prepared and punctual for the technical screening."
        }

D. DATA OUT (Rendered UI & Local History)
   - LocalStorage History Cache:
     * Key: "elitecruit-applicant-feedback-history" | "elitecruit-employer-feedback-history"
   - Rendered list of past feedback cards with star rating displays and dates.
   - Clean empty state ("No eligible targets available" / "No feedback recorded yet") when zero records exist.
